# Grounded AI Assistant

## Project Overview

Grounded AI Assistant is a beginner-friendly Python project that answers questions using information from a local knowledge document.

The project demonstrates document loading, keyword-based information retrieval, basic rule-based guardrails, automated evaluation, and estimated text-token usage logging.

## Features

* Loads AI knowledge from a local text document.
* Retrieves relevant sections using keyword matching.
* Rejects selected unsafe requests using simple keyword rules.
* Redirects off-topic questions.
* Evaluates retrieval and guardrail behaviour using automated tests.
* Saves evaluation results to a CSV file.
* Logs approximate text-token counts and estimated external API cost.

## Requirements

* Python 3
* No external Python packages are required by the current implementation.

## How to Run

Activate the virtual environment if needed, then run:

```powershell
python app.py
```

Ask a question about a topic in the knowledge document.

Type `exit` to close the application.

## Run the Evaluation

Run:

```powershell
python evaluate.py
```

The evaluation script checks expected retrieval results and guardrail behaviour.

The results are saved in `evaluation_results.csv`.

## Evaluation Results

The current evaluation dataset contains seven test cases.

* Tests passed: 7
* Tests failed: 0
* Evaluation score: 100%

This score represents performance on the included test cases only. It does not establish that the assistant is always correct or safe.

## Usage and Cost Tracking

The application records interactions in `usage_log.csv`.

Token counts are rough estimates based on text length. They are not actual model-token counts.

The current application does not call an external AI model API. Therefore, its external API cost is ₹0 for the recorded interactions.

## Limitations

* Retrieval uses keyword matching rather than semantic search.
* Responses are retrieved from the knowledge document, not generated by a language model.
* Guardrails use simple keyword rules and may miss differently worded unsafe requests.
* Evaluation covers a small, predefined test set.
* Token usage is estimated rather than measured using a model tokenizer.

## Future Improvements

* Add semantic search using embeddings.
* Integrate a language model API for grounded answer generation.
* Improve guardrails and test them against more varied prompts.
* Expand the evaluation dataset.
* Measure actual model token usage and API costs after API integration.

## Conclusion

This project demonstrates the basic components of a grounded assistant: local knowledge retrieval, simple guardrails, automated evaluation, and usage logging. It is a prototype that can be extended into a more capable retrieval-augmented generation system.
